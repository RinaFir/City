# NOCTURNE CSS City — фактический статус

## Аудит исходного прототипа — 2026-11-26

Проверены `index.html`, `styles.css`, `app.js` и прежний `README.md` в `learning-arcade/`.

### Что реально есть

- Статическая страница с тремя демонстрационными режимами: Selector Lab, Flex Arena и Grid Garden.
- В Selector Lab браузерный `querySelectorAll()` действительно проверяет CSS-селектор и подсвечивает совпавшие карточки.
- Flex Arena меняет несколько Flexbox-свойств через готовые выпадающие списки.
- Grid Garden меняет колонки и промежутки через готовые выпадающие списки.
- Есть адаптивные CSS-правила для узкого экрана.

### Что пока не реализовано

- Нет общего редактора, принимающего обычные CSS-правила и применяющего их к игровой сцене.
- Нет изолированной сцены в `iframe`.
- Нет заданий с проверяемой целью, банка задач, справочника, скрытой подсказки и доступного по запросу решения.
- Нет пропуска заданий и сохранения прогресса.
- Нет районной карты NOCTURNE и городских DOM-сцен. Текущие карточки, шахматные фигуры и сад — демонстрационные заглушки, а не нужный игровой мир.

### Технический долг прототипа

- `showWorld()` заменяет содержимое `.experiment` через `innerHTML`, поэтому узлы и обработчики предыдущего режима уничтожаются и создаются заново.
- В `app.js` одновременно существуют начальные ссылки на DOM-узлы и повторное создание аналогичных узлов при переключении режима. Это усложняет поддержку и создаёт риск работы с устаревшими ссылками.
- README описывает ранний Code Arcade и перечисляет функции как готовые; это описание не соответствует цели NOCTURNE и должно быть заменено.

### Вывод и следующий рабочий фрагмент

Прототип можно использовать как источник отдельных приёмов (живой вызов браузерного API и базовые стили), но не следует наращивать его текущую структуру. Следующий фрагмент — собрать единый каркас NOCTURNE: оставить существующий статический запуск, заменить демонстрационную страницу на городской экран и подключить изолированную DOM-сцену с настоящим CSS-полем. После этого на этот каркас можно подключать конфигурации заданий.

Проверка на реальном браузере в рамках этого аудита не выполнялась. Выводы выше основаны на чтении исходных файлов.

## Городская DOM-сцена — 2026-11-26

Создана отдельная сцена `scenes/city/` и встроена на главную страницу через `iframe`.

- Три здания с отдельными DOM-структурами: крыши, таблички, этажи, окна и входные группы.
- В разметке вручную присутствуют повторяющиеся элементы этажей и окон; это реальные узлы DOM, а не единая картинка.
- Окна имеют классы и состояния освещения; CSS задаёт фасады, перспективу, подсветку, небо, дальний силуэт города, улицу и атмосферные слои.
- Наведение на окно уже меняет его оформление через обычный CSS.
- Сцена имеет адаптацию для узких экранов и отдельный CSS-файл, поэтому её можно будет использовать как изолированную площадку для пользовательских правил.
- Главная страница показывает сцену в отдельном iframe.

Проверка структуры после загрузки: 3 здания, 23 этажей и 101 оконных DOM-элементов; iframe и подключение CSS присутствуют. Автоматический запуск в браузере и визуальная проверка пока не выполнялись.


## Обычный CSS-редактор и связь с iframe — 2026-11-26

- Под предпросмотром города добавлено обычное многострочное CSS-поле.
- Любое изменение в редакторе немедленно отправляется в iframe через `postMessage`; отдельная кнопка «Применить» не требуется.
- Внутри сцены пользовательские правила помещаются в отдельный `<style id="player-css">`, не перезаписывая базовый `city.css`.
- Кнопка сброса очищает только пользовательский CSS, базовая сцена остаётся нетронутой.
- Применение выполняется и после загрузки/перезагрузки iframe.
- Редактор принимает обычные CSS-правила; отдельный парсер или диагностический движок не добавлялся.

Проверка в браузере пока не выполнялась. Реализация проверена по структуре и связям исходников.

## Устройство заданий — 2026-11-26

- Добавлен небольшой банк из четырёх практических CSS-заданий для городской DOM-сцены.
- У задания есть условие, сворачиваемый справочник, скрытая подсказка и скрытое решение.
- CSS продолжает применяться к iframe сразу при вводе.
- Проверка сравнивает вычисленное браузером CSS-значение на целевом DOM-элементе; исходный текст и стиль написания кода не анализируются.
- Пропуск открывает следующее задание; после последнего возвращает к первому.
- Сброс очищает только пользовательский CSS текущего задания. Переход между заданиями тоже очищает код.
- Решение можно вставить в редактор, но оно не показывается автоматически.
- Никакая диагностика кода или система прогресса/аккаунтов не добавлялась.

### Самопроверка реализации

- Проверены согласованность идентификаторов элементов между HTML и JS, названия сообщений между родительской страницей и iframe, а также соответствие тестируемых CSS-свойств решениям.
- Проверка на реальном браузере ещё не выполнялась; визуальное поведение и фактический обмен сообщениями нужно подтвердить локальным запуском.
