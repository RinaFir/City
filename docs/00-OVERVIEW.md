# NOCTURNE CSS City — обзор

## 1. Цель и основные принципы

NOCTURNE CSS City — отдельное статическое веб-приложение для практического изучения CSS через игровые задания. Игрок пишет обычный CSS, а браузер применяет его к настоящим HTML-объектам городской сцены.

Главные приоритеты:

1. Широкое и последовательное покрытие основных тем CSS.
2. Большой банк разнообразных упражнений — ориентир первой полноценной версии: **около 240 задач**.
3. Постепенное усложнение и повторное применение уже изученных конструкций в новых ситуациях.
4. Видимое, непосредственное влияние написанного CSS на игровую сцену.
5. Простой интерфейс без необязательных подсистем.

Проект должен быть отдельным приложением в `learning-arcade/` и не смешиваться с Code Lab и другими инструментами репозитория.

### Принцип реального CSS

- Игровые объекты — настоящие HTML-элементы DOM, а не нарисованная картинка, имитирующая результат.
- Пользовательский код — обычный CSS, применяемый браузерным движком.
- Селекторы действительно выбирают элементы; Flexbox и Grid действительно размещают их; псевдоклассы и псевдоэлементы действительно меняют их поведение и вид.
- Иллюстрации города служат окружением и декорациями. Они не подменяют игровые объекты, которыми управляет CSS.
- Сцена должна наглядно показывать результат без необходимости читать отдельный разбор.

## 2. Атмосфера и визуальное направление

Рабочая художественная концепция — **NOCTURNE / ночной футуристический город**.

Основные признаки:

- Тёмные силуэты высотных зданий, плотная городская архитектура, крыши, эстакады, мосты и технические конструкции.
- Светлое относительно зданий звёздное вечернее небо: синие, индиго и лиловые оттенки.
- Лёгкий туман, облака, атмосферная перспектива и несколько планов глубины.
- Редкие световые акценты: розовые, бирюзовые, холодно-голубые и янтарные.
- Визуальное настроение аниме-пейзажа и масштабного футуристического мегаполиса; не уютное кафе, не сад, не милый городок и не сплошной кислотный киберпанк.

Городская среда должна быть частью игрового мира. Игровые сцены могут происходить на фасадах небоскрёбов, крышах, строительных площадках, транспортных узлах и световых системах.

**Важно:** визуальную основу внедрять с самого начала разработки. Не откладывать весь дизайн до финала. При этом редактор и код должны оставаться контрастными, строгими и удобными для чтения.

## 3. Структура приложения

Основной пользовательский маршрут:

1. **Город** — главная карта и вход в тематические районы.
2. **Район** — учебное направление CSS.
3. **Список заданий** — доступные упражнения и продолжение с последнего места.
4. **Игровая сцена** — конкретная городская конструкция или ситуация.
5. **Редактор** — поле CSS с немедленным применением к сцене.

Не создавать отдельные сложные разделы ради статистики, профиля, достижений или социальных функций.

Районы используют общий редактор, общие правила выполнения заданий и общую систему хранения прогресса. Район не должен быть жёстко привязан к одному CSS-свойству: знакомая сцена может возвращаться в следующих темах и получать новые задачи.

## 12. Что не входит в первую версию

Чтобы не раздувать объём и быстрее получить работающий продукт, не реализовывать:

- регистрацию и аккаунты;
- рейтинги и таблицы лидеров;
- социальные функции и мультиплеер;
- достижения ради достижений;
- сложную аналитику знаний;
- ИИ-проверку кода;
- собственный CSS-парсер;
- обязательные теоретические уроки перед задачами;
- обязательные разборы и отчёты после каждого уровня;
- сложную универсальную диагностику;
- отдельную уникальную механику для каждой CSS-темы;
- сложную физику разрушения и строительства в первой версии.

## 14. Критерии готовности первой полноценной версии

Первая версия считается готовой, когда:

- [ ] Приложение работает как отдельный проект в `learning-arcade/`.
- [ ] Есть единая городская карта и тематические районы.
- [ ] CSS-редактор применяет настоящий CSS к настоящей DOM-сцене.
- [ ] Сцена визуально показывает влияние кода.
- [ ] Есть полноценный район селекторов, псевдоклассов и псевдоэлементов.
- [ ] Есть практические районы Flexbox и Grid.
- [ ] Покрыты остальные запланированные основные группы CSS.
- [ ] Создано и проверено около 200–250 разнообразных задач.
- [ ] У каждого задания есть рабочее готовое решение.
- [ ] Справочник и подсказка доступны отдельно и не показываются постоянно.
- [ ] Задание можно пропустить.
- [ ] Прогресс сохраняется локально.
- [ ] Интерфейс пригоден для компьютера и телефона.
- [ ] Городская атмосфера соответствует заданному художественному направлению.
- [ ] Приложение опубликовано по постоянной ссылке.

## 15. Правила ведения разработки

- Двигаться по этапам, не распыляться на побочные функции.
- Не считать задачу завершённой только потому, что добавлены файлы или кнопки: функция должна реально работать.
- Не плодить параллельные версии и ветки под каждую мелкую правку; развивать одну актуальную версию проекта.
- Если внешняя проверка или сервис временно недоступны, не застревать бесконечно: выполнить доступную часть, зафиксировать ограничение и продолжить следующий пункт.
- Не заявлять о тестировании, если оно фактически не выполнялось.
- Приоритет при выборе между новой функцией и дополнительными заданиями — покрытие тем и качественное наполнение банка задач.

---

**Ключевая формула проекта:** игрок видит городскую задачу → пишет обычный CSS → браузер реально меняет городскую сцену → игрок проверяет результат и переходит к следующей задаче. Красота поддерживает обучение, а не заменяет его.
